# 路线可信性修复方案与审查

## 官方依据与方案修订

- [高德 Web 路径规划](https://developer.amap.com/api/webservice/guide/api/direction)：公交 city / cityd 分别为起终点城市，segments 为有序换乘路段；不能固定北京，也不能把同路段线路全部串联。
- [高德 SDK 公交自绘示例](https://developer.amap.com/demo/javascript-api-v2/example/bus-search/bus-custom)：SDK 使用 segment.transit.path；修订方案为自行绘制该轨迹，不再让 Transfer 自动画另一套路线。
- [W3C Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：左右方向键循环切换，Home / End 定位首尾，并保持焦点。
- [Node 子进程文档](https://nodejs.org/api/child_process.html)：Windows CMD 脚本不能直接作为可执行文件启动；沿用现有 smoke runner 的 Node + 本地 Playwright CLI。

## 执行结果

R1–R6 已实施并审查。无产品框架、重试层或新服务引入，原生路线视觉参数未改动。

### 回归中发现并修正

- 高德 LIVE 公交返回无铁路行程的 `railway: {via_stops: [], alters: [], spaces: []}`。仅凭对象存在判断铁路会误降级；改为有实际名称或距离才算铁路，并增加同结构单测。真实铁路缺失轨迹仍不冒充道路。
- 标签方向键最初切换成功但失焦。动态追踪定位到移动视图选择器把 body 也绑定成按钮，冒泡方向键触发视图切换并聚焦 body。三个选择器限为真实 button，并保留后台重绘前的标签焦点。
- 旧 SDK mock 没有拦截 BFF，造成默认用例实际读取外部道路。现在统一拦截，个别测试的显式 BFF fixture 仍可覆盖。默认回归不再依赖真实 BFF。
- 原 SDK 分步缓存的八段上限也会截断路线，已移除；真实来源随结果传递，SDK 不再写成 Web Service。
