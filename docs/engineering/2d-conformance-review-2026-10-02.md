## 联网核验与 v2 方案

1. F02：采用当前主版本内的修补，不使用 `--force` 或跨大版本升级。Hono 更新至 4.13.12（[官方公告](https://github.com/honojs/hono/security/advisories/GHSA-5r4p-p66f-jhc7) 要求至少 4.13.11）；Vitest 更新至 4.1.11（[官方公告](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)）。依赖项 brace-expansion 1.x 至少 1.1.21（[官方公告](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-q2hr-2g5m-vwhr)），js-yaml 保留兼容的 4.x 修补版本，不为只影响 5.x 的公告迁移主版本。公告存在不等于当前产品已被利用；更新后以本轮 audit 和回归核验。
2. F03：依据 [W3C 表单标签规范](https://www.w3.org/WAI/tutorials/forms/labels/)，使用 `for` / `id` 关联字段，补充输入能力和后续预览说明；修复已观察到的超长错误恢复，不新增 OCR 或上传接口。
3. F04：先对现有键盘路线测试增加真实 overlay 创建、高亮、清除断言，暴露 mock 与 SDK 接口差异，再修补测试替身。Mock 通过不替代真实高德白箭头的视觉验收。
4. F01：维护入口、产品总纲、2D 数据契约与视觉规则统一为 2D-only / schema v5 / 原版路线渲染加离散色号；旧商业化和质量记录明确标为历史，不删除封存实现、不启动 Kotlin。
