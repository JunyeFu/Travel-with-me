## 最小实现选择

- Kotlin + Jetpack Compose，单 app 模块，按界面/数据/服务分目录；不提前拆多模块。
- 保留 `Workspace → Trip → Day → Event` 和 locations ID 引用，最多三条路线，与当前 Web 相同。
- 首版本地保存一份 workspace JSON（应用私有文件，临时文件写完再替换以避免半写损坏）；不为三条路线引入数据库。外部导入按既有格式和数据完整性边界检查，替换前明确确认并留原文件。
- 文件互通采用 Android Storage Access Framework，系统选择 JSON 文件；跨端第一步是文件交接，不声称已实现账号/自动云同步。[官方文件接口](https://developer.android.com/training/data-storage/shared/documents-files)
- Compose 依赖使用固定稳定 BOM；编译器插件与 Kotlin 对齐。M1 建工程时锁定 AGP/Gradle/Kotlin 的兼容组合并实际构建，不使用动态版本。[官方 Compose BOM](https://developer.android.com/develop/ui/compose/bom)、[官方 AGP 兼容说明](https://developer.android.com/build/releases/agp-9-0-0-release-notes)
- 高德 Android SDK 需要 Android 平台应用配置，不能拿 Web JS Key 当原生 Key。2D 展示不等于重新引入已封存的项目 3D 功能。
- DeepSeek 密钥继续只在现有服务端环境；APK 不包含它。M3 复用 `/_ai/extract-guide` 及需要的 POI/路线服务，不照搬浏览器 SDK 代理。
- 当前 BFF 未在公网部署；M2/M3 联调时需要手机可达的开发地址，正式远端服务另按部署授权执行。离线 M1 不依赖它。

## 样本使用说明

`work/user-simulation/routes.workspace.json` 可通过现有 Web 的行程菜单 → 导入工作区 JSON → 预览 → 保存恢复点并替换。会替换当前三条路线，因此先导出自己的工作区。

三份攻略 Markdown 可分别复制到 AI 攻略导入入口；三张 `*-ai.png` 是生图素材，实际应用长图来自应用下载按钮，两者分开保存。地点坐标初始为空，未伪造 geocoding 或已验证预约；导入后再匹配和人工修正。

模拟操作证明功能链可运行，不等于真实用户留存、满意度或节省时间已被测量。
